# Мини-приложение для записи в барбершоп

Учебное Telegram Mini App: клиент выбирает услугу, мастера, день и время, а страница отправляет выбор боту.
Это одна статическая страница (`index.html`, `style.css`, `app.js`) без сборки и без серверной части.
Услуги, мастеров и расписание страница получает от бота в адресе, поэтому её не нужно править
при смене цен, услуг или мастеров.

## Как это работает

Вверху — шапка с названием и адресом барбершопа (из данных бота) и индикатор шагов.

1. **Услуга**: карточки с ценой и длительностью — из данных бота.
2. **Мастер**: «Любой мастер» или конкретный мастер с аватаром-инициалами и коротким описанием.
   Под описанием — сколько у него свободных часов на неделе; мастер без свободного времени недоступен.
   Для «Любого мастера» слот свободен, если свободен хоть кто-то, а к кому записать, решает бот.
   Если свободного времени нет ни у кого, вместо списка — сообщение «Нет свободного времени».
3. **Дата и время**: дни горизонтальной лентой (сколько передал бот, сейчас 7 начиная с сегодня),
   сразу открыт ближайший день со свободным временем. Время — по часу, группами «Утро / День / Вечер».
   Занятые и прошедшие часы видны, но выбрать их нельзя.
4. **Проверка**: итоговая карточка; кнопка «Записаться · цена» — это `Telegram.WebApp.MainButton`,
   а возврат на предыдущий шаг идёт через `Telegram.WebApp.BackButton`. При выборе срабатывает
   `HapticFeedback`.

Цвета берутся из темы Telegram (`themeParams`), поэтому страница сама подстраивается под светлую и тёмную тему.
Вёрстка рассчитана на телефоны шириной 320–430 px, внешних библиотек и шрифтов нет.

При изменении `app.js` или `style.css` увеличьте версию `?v=...` в `index.html`, иначе Telegram
может показать старую версию из кэша.

### Данные от бота

Бот передаёт всё одним параметром адреса `d` — JSON в UTF-8, закодированный в base64url без `=`:

```
https://<логин>.github.io/<репозиторий>/?d=eyJ2IjoxLCJkIjoiMjAyNi0xMC0xMSIs...
```

Внутри — компактный JSON с короткими ключами, чтобы адрес оставался коротким
(с тремя мастерами и пятью услугами — около 900 символов):

```json
{
  "v": 1,
  "d": "2026-10-11",
  "n": 7,
  "h": [10, 19],
  "s": [["haircut", "Мужская стрижка", 1500, 45], ["beard", "Стрижка бороды", 800, 30]],
  "m": [["alex", "Алексей", "Классика и фейды", [0, 6, 0, 1023, 0, 0, 0]]],
  "b": ["Барбершоп «Бритва»", "ул. Пушкина, 10"]
}
```

| Ключ | Что значит |
|------|-----------|
| `v` | Версия формата (сейчас 1) |
| `d` | Первый день записи `ГГГГ-ММ-ДД` (по часам сервера бота) |
| `n` | Сколько дней показывать |
| `h` | Первый и последний час записи |
| `s` | Услуги: `[код, название, цена, минуты]`. Минуты (длительность) необязательны |
| `m` | Мастера: `[id, имя, описание, занятость]`. Занятость — по числу на каждый из `n` дней, битовая маска часов: бит 0 — первый час (`h[0]`), бит 1 — следующий и т. д. Например, `6` = биты 1 и 2 = 11:00 и 12:00 заняты, `1023` — заняты все 10 часов |
| `b` | Необязательно: `[название барбершопа, адрес]` для шапки и итоговой карточки |

Если параметра нет или он испорчен, в Telegram страница показывает сообщение «Не удалось загрузить
расписание», а в обычном браузере открывается с демо-данными.

### Что получает бот

После подтверждения страница вызывает `Telegram.WebApp.sendData` с такой строкой JSON:

```json
{"service":"haircut","master":"boris","date":"2026-10-08","time":"11:00"}
```

`service` — код услуги, `master` — id мастера или `any` («Любой мастер»). Цену страница не отправляет:
бот берёт её из своего списка. Бот получает строку в сообщении в поле `web_app_data.data`.
После отправки Telegram сам закрывает мини-приложение.

> **Важно.** `sendData` работает, только если страница открыта через обычную кнопку клавиатуры
> (`KeyboardButton` с полем `web_app`). Если открыть её через инлайн-кнопку, отправить данные не получится:
> страница это определяет, прячет кнопку подтверждения и показывает предупреждение.

## Проверка локально

Вне Telegram страница работает в демо-режиме: вверху появляется пометка, кнопки «Назад» и
«Подтвердить запись» показываются прямо на странице, а после подтверждения на экран выводится
JSON, который получил бы бот.

Запустите любой простой веб-сервер в папке проекта, например:

```bash
python -m http.server 8000
```

Откройте в браузере:

- http://localhost:8000/ — с встроенными демо-данными (пять услуг и три мастера);
- http://localhost:8000/?d=... — с настоящими данными: возьмите адрес, который собирает бот
  (функция `miniapp_url` в `bot.py`), и замените в нём начало на `http://localhost:8000/`.

Можно открыть и сам `index.html` двойным щелчком, но через сервер поведение ближе к настоящему.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и отправьте в него файлы проекта:
   ```bash
   git add .
   git commit -m "Мини-приложение для записи в барбершоп"
   git branch -M main
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```
2. В репозитории откройте **Settings → Pages**.
3. В разделе **Build and deployment** выберите **Source: Deploy from a branch**,
   ветку `main` и папку `/ (root)`, нажмите **Save**.
4. Через минуту-две страница будет доступна по адресу `https://<логин>.github.io/<репозиторий>/`.
   GitHub Pages работает по HTTPS, а Telegram только с таким адресом и открывает мини-приложения.

Этот адрес (с параметром `d`) бот указывает в `KeyboardButton` с `web_app`.
Страницу и бота нужно обновлять вместе: формат данных в адресе и в `sendData` у них общий.

## Безопасность

В проекте нет токенов, ID и других секретов: страница ничего не знает о боте и только отправляет выбор
через `sendData`. Токен бота хранится только в коде бота, не здесь. Перед записью бот должен
сам ещё раз проверить услугу, мастера и что выбранный слот у него свободен: данные со страницы
(и параметр `d` в адресе) может подменить кто угодно. Имена и описания из адреса страница выводит
только как текст (`textContent`), поэтому HTML в них не выполнится.
